# M9 典型失败与评估缺陷

2026-10-17。所有真实案例来自 `m9-run.json` 的单次运行，未挑选重跑最佳结果，未更改运行时 Prompt 或参考答案以提高分数。人工语料不是用户业务资料。

## 1. R04：Dense 无法区分相近错误码

问题是 E1001，Dense Recall@1=0，FTS/RRF/Rerank 的 Recall@1=1。相近数字编号在语义向量中容易接近，完整标识符词项检索补足此样本。不能因此声称混合检索对所有问题都更好。

改进候选：扩展不同格式/大小写/分隔符的编号样本；检查候选召回，再评估排序。没有在本版新增检索算法。

## 2. R15：Sparse 与 RRF 使语义问题排名下降

“一周可以在家上班几天？”：Dense Recall@1=1，Sparse=0、RRF=0，Rerank恢复到1。中文二元组偏字面匹配，融合可能给无关候选加分。这是融合成本与重排价值的具体例子，不把每层都包装成正向提升。

## 3. A02：没有工具证据却触发引用错误

Agent面对 E1001，没有工具调用、没有可见证据，最终 `invalid_citation`。系统防护拦截了非法引用，但用户任务失败。
原始未通过校验的候选回答没有被此运行的评估wrapper保存，因此不猜测具体伪造编号，也不将错误称为provider故障。

改进候选：在后续明确产品策略后评估“知识问题先检索”的路由或Prompt；本版仅记录问题，不改M8行为。

## 4. A04/A05：安全拒答不代表任务完成

ZX-200、ZX-200S均有资料，模型没有调用工具，服务端给出固定无证据提示。Graph正常完成，但任务应判失败。Agent规则选择符合率9/12；12次实际提出的工具调用都通过Schema，这不能证明未调用工具的三个任务成功。

## 5. R13：评估数据本身有缺陷

冻结的规则facts误写“七天/7天”，实际Context是“备份保留三十天”，模型正确回答三十天。原始规则仍记失败，不能通过改答案、删样本或悄悄调整分母抬高成绩。
单独的模型辅助复核记录正确性1、证据支持1，并保留理由和原始record hash。未来若修正，应发布新dataset版本，旧报告保持可复现；当前没有替换v1。

另一个范围缺陷：A12标记document_key=foreign，但执行器没有创建另一个租户的文档，因此A11/A12都实际测试不存在ID。报告明确不把A12当跨租户质量证据；真实跨租户防护由既有集成测试验证。未来数据版本应修正环境构建，而不是把现有结果夸大。

## 6. 规则评分可能误判否定与拒答

单元反例“不是12天 [S1]”含有正确关键词，规则可误判通过。拒答规则包含“没有/无法”等词，也可能将带限定条件的正常答案误判为拒答。
规则是筛选与诊断代理，不是语义评审。正确性、Faithfulness和引用支持由独立标注导入；本次只有11条Codex模型辅助复核，不冒充人工标注或总体结论。

## 7. 预算与延迟

真实运行没有超预算/超时案例，不能编造一次真实超时来充实报告。M8已有预算及取消测试，M9继续回归；它们使用Fake模型证明程序边界，不代表真实模型失败频率。
本次冷加载+整份人工语料编码35.468秒；暖运行RAG median1.094秒、Agent median1.702秒。A01用两次检索解释简单年假问题，耗时3.469秒；A08空知识库仍尝试两次检索。重复工具循环带来额外Token和等待，单Agent不是天然比普通RAG更高效。
逐题时间不含额外四路排名对比，不是端到端HTTP或SSE首Token基准。CPU线程取消无法立即杀死原生推理，仍需容量保留；没有部署级限流或监控告警平台。

## 8. Faithfulness 与引用校验的限制

来源编号存在只能证明身份合法；即使答案正确，也可能来自模型先验。支持判断只允许引用本次发送的Context或工具证据，不允许从全库补证。
